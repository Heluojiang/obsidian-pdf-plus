# i18n conventions

The UI text of PDF++ lives in `src/lang/locale/en.ts` (English, source of truth) and
`src/lang/locale/zh.ts` (Simplified Chinese). Call sites use `t('<key>')`.

> Background: this adds the strings that [#587](https://github.com/RyotaUshio/obsidian-pdf-plus/pull/587)
> and [#588](https://github.com/RyotaUshio/obsidian-pdf-plus/pull/588) did not extract. The
> 759 keys those pull requests introduced were not, in fact, every user-facing string;
> `pnpm scan-i18n` finds the rest.

```ts
import { t } from 'lang';

new Setting(el)
    .setName(t('settings.enablePDFEdit.name'))
    .setDesc(t('settings.enablePDFEdit.desc'));
```

## Adding a string

1. Add `'<key>': '<English>'` to `src/lang/locale/en.ts`.
2. Add `'<key>': '<中文>'` to `src/lang/locale/zh.ts`.
3. Replace the literal at the call site with `t('<key>')`.

**Both files, always.** `zh.ts` is typed as `Record<keyof typeof en, string>`, so a key
present in `en.ts` but missing from `zh.ts` fails `pnpm build` at the `tsc` step. That is
deliberate: it is what stops the Chinese table from silently rotting behind English.

Keys go in a `// ---- strings missing from #588 ----` block at the end of the object in both files,
sorted by key. Keys added by upstream PR #588 keep their existing position; do not
reorder them.

## Key naming

Flat dotted identifiers. The first segment is the owning namespace.

| Source | Pattern | Example |
| --- | --- | --- |
| `src/settings.ts` | `settings.<settingProperty>.name` / `.desc` | `settings.enablePDFEdit.name` |
| `src/settings.ts`, long help | `settings.<settingProperty>.help` | `settings.vimRcFilePath.help` |
| `src/settings.ts`, section heading | `settings.heading.<sectionId>` | `settings.heading.open-backlink` |
| `src/settings.ts`, misc copy | `settings.misc.<slug>` | `settings.misc.available-only-on-macos` |
| `src/settings.ts`, dropdown option | `settings.<settingProperty>.option.<optionKey>` | `settings.paneTypeForFirstMDLeaf.option.tab` |
| `src/main.ts` | `main.<slug>` | `main.customize` |
| `src/lib/index.ts` | `libIndex.<slug>` | `libIndex.file-already-exists.notice` |
| `src/lib/commands.ts` | `libCommands.<slug>` | `libCommands.link-copied-to-clipboard.notice` |
| `src/lib/copy-link.ts` | `libCopyLink.<slug>` | `libCopyLink.display-text-format-is-invalid.notice` |
| modals | `modals<FileName>.<slug>` | `modalsPdfComposerModals.page-size` |
| `src/context-menu.ts` | `context-menu.<slug>` | `context-menu.delete-annotation` |
| `src/color-palette.ts` | `color-palette.<slug>` | `color-palette.customize` |
| `src/vim/*` | `vim<Submodule>.<slug>` | `vimCommandLine.unknown-command.notice` |
| anything else | `<camelFileName>.<slug>` | `drag.move-into`, `bib.year.help` |

`<slug>` is the English text lowercased, with runs of non-alphanumeric characters
collapsed to `-`, truncated to 40 characters, and suffixed with the sink when useful
(`.notice` for `new Notice`, `.title` for a menu title, `.help` for a hint).

## Interpolation

`t(key, params)` replaces `{name}`:

```ts
new Notice(t('context-menu.failed-to-insert-the-page.notice', { plugin: plugin.manifest.name }));
```

Use `{plugin}` for `plugin.manifest.name`. Use `{v0}`, `{v1}`, … only for a value that
appears once and has no better name.

`t()` returns a `string`. When the original was assembled from several literals, either
widen the key into one sentence with placeholders, or give each literal its own key and
concatenate — never translate a half-sentence in isolation if a single key can carry it.

## Do not translate

- Setting identifiers, `PDFPlusSettings` keys, `DEFAULT_SETTINGS` keys.
- Deep links: `obsidian://pdf-plus?setting=<id>`, `?setting=heading:<id>`.
- Heading `id` arguments to `addHeading(heading, id, ...)`.
- Dropdown **option keys**: they are stored in `data.json`. Only the label is translated
  (`addDropdownSetting('rectImageFormat', { 'file': 'Create & embed image file' })` — the
  left-hand side stays, the right-hand side becomes `t(...)`).
- Command `id`s, `setSection` ids, `Menu.addSections` ids, CSS classes, DOM ids,
  `lucide-*` icon names, URLs, file paths, Obsidian core command ids.
- Values written to `data.json`: `DEFAULT_SETTINGS` template/color **names** and template
  **bodies**, `PAGE_LABEL_NUMBERING_STYLES`, `PageSizes`, `IMAGE_EXTENSIONS`,
  `citationIdPatterns`, `vimrcPath`, `PATH`.
- Product names: PDF++, Canvas, Obsidian, Google Scholar, Dataview, Hover Editor, AnyStyle,
  Surfing, BibTeX, CSL-JSON, and every `:ex` command the user types.
- Author and sponsorship information (it points at the upstream author on purpose).

## Verification

```sh
pnpm build          # tsc proves en/zh parity, then bundles
pnpm lint
pnpm scan-i18n      # == node scripts/scan-ui-strings.mjs
```

The scan reports strings that are still hard-coded. Anything it reports must either be
translated or listed in `scripts/ui-string-whitelist.json` with a reason. Every whitelist
entry needs a `reason`; adding one is a decision, not a shortcut.

The whitelist has three buckets:

| Bucket | Meaning |
| --- | --- |
| `userVisibleNotTranslatedIntentionally` | shown to users, deliberately English (platform and plugin names, format names) |
| `persistedUserData` | written to `data.json`; translating rewrites user settings |
| `notUserVisible` | CSS, PDF-spec constants, debug-report keys, console output, thrown errors |

## Bulk additions

For a large batch — merging an upstream release, say — use the fragment workflow instead
of editing the tables by hand:

```sh
# 1. write scripts/.i18n/keys-<TAG>.en.ts and keys-<TAG>.zh.ts, one entry per line:
#       'key': 'value',
#    (a bare list at one tab of indentation, starting with a // comment line)
# 2. validate and splice into both tables:
node scripts/merge-locale-fragments.mjs --check   # validation only
node scripts/merge-locale-fragments.mjs           # rewrite the added block
```

The merge is idempotent: it replaces the whole `// ---- strings missing from #588 ----` block rather
than appending, so re-running it never duplicates keys. It refuses to run when a key is
missing from one side, defined twice, or already exists above the block.

## Upstream merge checklist

Because every call site now goes through `t()`, an upstream merge will bring in new
hard-coded English strings that nothing routes through the table. After
`git merge upstream/main`:

1. Resolve conflicts. Keep upstream's new strings as they are for now.
2. `pnpm scan-i18n` — this lists everything that arrived un-translated.
3. Translate each finding: add to `en.ts` and `zh.ts`, replace the literal with `t()`.
4. `pnpm build` (en/zh parity), `pnpm lint`, `pnpm scan-i18n` again.
